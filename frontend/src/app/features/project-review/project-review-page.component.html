GitHub Live Application

URL Shortener

A focused full-stack application for creating, managing, redirecting, and analyzing shortened URLs.

It combines an Angular frontend with a Java/Spring Boot backend and MySQL database, with features such as URL lifecycle management, analytics, idempotency, concurrency protection, rate limiting, validation, and observability. The application uses a modular monolith architecture to keep the solution simple and maintainable, while AI-assisted development was used throughout the engineering process under developer review and decision-making.

AI recommendations were reviewed against the project scope, architecture, and complexity before being accepted, refined, deferred, or rejected.

Rejected

Microservices

AI suggested separating URL Management, Redirect, and Analytics into independent services. I rejected this because the project does not require independent scaling or deployment, and the added distributed-system complexity was not justified.

Deferred

Redis

Redis was considered for distributed rate limiting and caching. I deferred it because the current deployment does not require shared state across multiple backend instances.

Accepted + Refined

Concurrency Protection

AI identified the risk of concurrent updates. I refined the solution by choosing optimistic locking with @Version and If-Match, which fits the expected low-contention workload.

Accepted + Validated

Idempotency

AI suggested protecting URL creation from duplicate requests. I accepted the approach after validating replay behavior, request fingerprinting, conflict handling, and persistence.

Modified / Rejected

Extra Abstractions

Some suggested abstractions increased indirection and code complexity without enough benefit. I kept the useful parts and removed unnecessary layers to keep the codebase simple and maintainable.
